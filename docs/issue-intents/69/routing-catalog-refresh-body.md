# Outcome

Provide a repository-owned, fail-closed way to import a freshly generated OpenCode model catalog into Factory development evidence without changing routes, providers, benchmarks, budgets, or fallback semantics.

# Scope

- Add a deterministic command that reads the approved generated user catalog, verifies schema, freshness, provider completeness, and every enabled route model, and writes only the route-relevant Factory catalog snapshot.
- Pin the command to Factory's trusted Node runtime and repository source through an exact interactive permission.
- Add tests for stale, incomplete, malformed, missing-route, and successful catalog inputs.
- Record the stale-catalog dead-end 5-Whys and update continuation evidence.

# Out of scope

- Refreshing provider catalogs directly, benchmarking models, promoting routes, changing providers, changing route assignments or variants, changing provider budgets, enabling cloud fallback, or editing evidence timestamps without generated source evidence.

# Acceptance criteria

- A fresh session can import an approved generated catalog through one repository-owned command and Factory doctor becomes launch-ready when all other gates pass.
- The imported snapshot preserves the source generation and timestamp and contains every active model referenced by enabled Factory routes or startup fallbacks.
- Missing, stale, malformed, failed-provider, or incomplete source evidence fails without changing the tracked last-known-good catalog.
- Route registry, benchmark evidence, provider policy, and cost/fallback semantics remain byte-for-byte unchanged.

# Verification

- Focused Node tests for successful and rejected imports.
- Exact policy and manifest integrity tests.
- Cost-router tests and config-hook smoke check.
- Factory doctor before and after a fresh-session import.
- Independent trust-boundary review and hosted Factory checks.

# Dependencies

- Parent canonical-development issue #69 and consolidation map issue #68.
- A catalog generated by the approved OpenCode model-routing refresh procedure.

# Authority and privacy

- This issue authorizes repository-local development tooling, tests, and import of non-secret generated catalog evidence only.
- It does not authorize paid model calls, benchmarks, route promotion, provider or budget changes, external publication, repository setting changes, or credential access.
- Catalog import must not copy credentials, tokens, local paths, or private provider metadata.
